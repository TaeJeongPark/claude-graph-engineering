# 그래프 엔지니어링

여러 에이전트가 필요한 작업은 대화로 조율하지 않고 그래프로 실행한다: 노드는 서브에이전트(`graph-*`), 엣지는 Workflow 스크립트의 제어 흐름, 엣지를 따라 흐르는 상태는 스키마로 검증된 JSON이다.

- 저장된 그래프: `/graph-build`(작업 DAG 병렬 구현 + 검증·리뷰 게이트), `/graph-review`(관점별 탐지 → 반증), `/graph-investigate`(재현 → 가설 → 증거 → 판정). 새 그래프를 만들 때는 `graph-design` 스킬을 따른다.
- 그래프는 에이전트를 여러 개 띄워 토큰을 많이 쓴다. 사용자가 그래프·워크플로를 요청했을 때만 실행하고, 그렇지 않으면 무엇을 할 수 있는지와 대략의 규모를 알리고 묻는다. 한두 파일짜리 작업은 직접 한다.
- 그래프가 끝나면 반환된 상태(`DONE`/`INCOMPLETE`/`BLOCKED`)와 실패·건너뛴 작업을 그대로 보고한다. 그래프의 노드는 커밋하지 않는다.
- 실행 기록은 프로젝트의 `.claude/graph/runs/<이름>/`(`plan.json`, `progress.md`)에 남는다. 중단된 실행은 `/graph-build`에 `{resume: true, outDir}`을 넘겨 이어간다.
