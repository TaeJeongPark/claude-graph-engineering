# 그래프 설계

만들 그래프: $ARGUMENTS

그래프는 **노드**(서브에이전트 호출), **엣지**(스크립트의 제어 흐름), **상태**(엣지를 따라 흐르는 스키마 검증된 JSON), **게이트**(다음 엣지를 정하는 판정)로 이루어진다. 흐름은 모델이 아니라 코드가 정한다.

## 0. 그래프가 맞는 일인지 먼저 판단한다

아래에 하나도 해당하지 않으면 그래프를 만들지 말고 그 이유를 사용자에게 말한다.

- 서로 독립인 일이 여러 개라 병렬로 하면 빨라진다.
- 작성자와 다른 시각의 판정(검증, 반증, 리뷰)이 결과의 신뢰를 높인다.
- 한 컨텍스트에 담기지 않는 규모다(여러 모듈 조사, 대량 변환).
- 같은 절차를 여러 번 반복 실행할 것이다.

한 세션에서 순서대로 하면 되는 일, 반복마다 새 세션으로 긴 계획을 처리하는 일(그건 루프다)은 그래프가 아니다.

## 1. 종이에 먼저 그린다

코드를 쓰기 전에 다음을 사용자에게 짧게 보여 준다.

- **노드 목록**: 노드마다 하는 일 한 줄, 읽기 전용인지 쓰기인지, 입력과 출력.
- **엣지**: 순차, 병렬 분기, 합류, 조건 분기, 사이클. 텍스트 그림이면 충분하다.
- **게이트**: 어떤 판정이 어떤 엣지를 고르는가.
- **정지 조건**: 모든 사이클의 횟수 상한, 병렬 폭 상한, 결과가 비었을 때의 조기 종료.
- **예상 에이전트 수**: 최악의 경우 몇 번 호출되는가.

## 2. 설계 규칙

- **노드는 한 가지 일만 한다.** 찾는 노드와 판정하는 노드를 나눈다. 자기 결과를 자기가 판정하게 하지 않는다.
- **출력은 스키마로 받는다.** 다음 노드나 분기 조건이 쓰는 값은 `schema`로 강제한다. 자유 텍스트를 정규식으로 파싱하지 않는다.
- **노드는 앞 노드의 대화를 보지 못한다.** 필요한 것은 전부 프롬프트에 넣거나, 파일 경로로 넘긴다.
- **쓰기 노드는 동시에 같은 파일을 고치지 않게 한다.** 쓰기 범위가 겹치지 않는 것만 병렬로 돌리거나, 순서를 정하거나, `isolation: 'worktree'`를 쓴다(비용이 크고 병합 단계가 필요하다).
- **병렬 쓰기 직후의 검증은 믿지 않는다.** 다른 노드가 파일을 고치는 중이면 타입 체크가 엉뚱하게 실패한다. 병렬 구간이 끝난 뒤(조용한 트리) 판정한다.
- **모든 사이클에 상한을 둔다.** `while (true)`에는 반드시 횟수나 "새 결과 없음" 조건이 있어야 한다.
- **실패도 반환값이다.** `agent()`는 `null`을 돌려줄 수 있다. 걸러내고, 무엇이 빠졌는지 `log()`와 반환값에 남긴다. 상한 때문에 버린 항목도 조용히 버리지 않는다.
- **기본은 `pipeline()`**, 앞 단계의 전체 결과가 한꺼번에 필요할 때만(중복 제거, 0건이면 조기 종료) `parallel()`로 모은다.
- **모델은 지정하지 않는 것이 기본이다.** 세션 모델을 상속한다. 호출자가 `args.models`로 바꿀 수 있게만 한다.
- 기존 노드(`graph-planner`, `graph-implementer`, `graph-verifier`, `graph-reviewer`, `graph-analyst`)로 되면 새 에이전트를 만들지 않는다. 역할의 지침이 정말 다를 때만 `.claude/agents/`에 추가한다.

## 3. 작성

1. 템플릿을 복사해 시작한다: `${CLAUDE_CONFIG_DIR:-~/.claude}/graph/templates/graph.template.js`
2. 저장 위치: 이 프로젝트에서만 쓰면 `.claude/workflows/<이름>.js`, 모든 프로젝트에서 쓰면 `~/.claude/workflows/<이름>.js`. 저장하면 `/<이름>`으로 실행된다. 이름이 `graph-`로 시작하는 파일은 그래프 엔지니어링 설치가 관리하므로 그 접두사를 쓰지 않는다.
3. 스크립트 제약: 순수 JavaScript(타입 주석 없음), `meta`는 리터럴, `import`·파일시스템·`Date.now()`·`Math.random()` 사용 불가. 파일을 읽고 쓰는 일은 노드에게 시킨다. 자세한 API는 `workflow-authoring` 스킬을 따른다.

## 4. 검사 (토큰을 쓰지 않는다)

```bash
graph-check <스크립트>                                  # meta, 문법, 금지 API, phase 일치
graph-check <스크립트> --sim --args '<json>'            # 노드를 스텁으로 바꿔 끝까지 실행
graph-check <스크립트> --sim --fixture <픽스처.mjs>     # 노드별 응답을 지정해 분기·사이클 확인
```

픽스처는 `export default (prompt, opts, n) => 값`이다. `opts.label`로 노드를 구분해 실패·빈 결과·blocked 를 돌려주고, 다음을 확인한다.

- 실패 경로에서 사이클이 상한에서 멈추는가
- 결과가 0건일 때 뒤 단계를 건너뛰는가
- 최대 동시 실행 수와 총 호출 수가 예상과 맞는가

검사를 통과하기 전에는 실제로 실행하지 않는다. 실제 실행은 사용자가 요청할 때만 한다.
